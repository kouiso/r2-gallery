title: オフライン保存の目録が接続先ごとに分かれておらず、別の接続先の写真が「保存済み」に見える
labels: (none)

## 起きていること
オフライン保存の目録は `lib\0key` をキーにしていて、接続先（エンドポイント）が入っていません（`flutter/lib/src/offline/offline_store.dart` の 113 行目あたり）。

接続先 A で写真をオフライン保存したあと、同じライブラリ id を持つ接続先 B に切り替えたとします。B に同じキーの写真があると、次のことが起きます。

- 一覧で B の写真に「保存済み」の印が付く
- ビューアが回線なしで開く時に、B の写真ではなく A で保存した中身を出すおそれがある
- オフライン保存の画面に、A の項目と B の項目が混ざって並ぶ

これは #131 より前から「切断 → 別の接続先へ接続」で起きていました。#131 の「接続先を変更」で、ワンタップで起きるようになっています。#131 では転送が残っているあいだ別の接続先への保存を止めていますが、オフライン保存済みの中身はそのまま残ります。

## 関連: 途中の分割アップロード
転送は送るたびに今の接続を読みます（abort も同じ）。#131 では、送り終えていない行があるあいだは別の接続先への保存を止めています。ただ、行は「取り消す」を押した時点で取り消し扱いになり、A への abort はそのあとで送られます。そのため、次の場合は A に途中の分割アップロードが残ります。

- 取り消してすぐ B へ切り替え、abort が B に送られた
- abort が失敗した（圏外など。失敗はログに出すだけで、やり直さない）

残った分は R2 のライフサイクルで消えるまで容量を使い続けます。

## オーナーに決めてほしいこと
1. 目録のキーに接続先（ホスト）を入れる。既存の目録は、今の接続先のものとして読み替える
2. 接続先を切り替えた時に、オフライン保存をすべて消す（切り替えの前に確認を出す）
3. 接続先ごとに目録を分け、切り替えたら今の接続先の分だけを見せる（前の接続先の分は残す）
4. 今のまま（同じキーの別物はまれなので、注意書きだけにする）

途中の分割アップロードについては、次のどちらかを決めてください。

- a. 取り消しの時、積んだ時の接続先へ abort を送る（行に接続先を覚えさせる）
- b. R2 のライフサイクルに任せる（今のまま）
