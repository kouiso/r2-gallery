## 概要
`secrets-scan` の gitleaks が、PR でも main への merge push でも **0 コミットしか検査していなかった**ため、範囲指定を直します。

### 原因
- `.github/ci/gitleaks.sh` は `--log-opts="--no-merges --first-parent <base>..<head>"` で走る
- PR イベントでは `CI_SCAN_HEAD` が `github.sha`（PR のマージ参照）になる。`--first-parent` はマージコミットの第1親（base 側）しかたどらず、`--no-merges` がマージコミット自体を除くので、範囲が空になる
- main への push も、このリポジトリは「Merge pull request」形式でマージしており、PR のコミットは第2親側にあるため同様に空
- 実際、#128 のレビューで、`curl-auth-header` に掛かる README のコミットがあっても `secrets-scan` が約 6 秒で green になっていた

### 変更
- `.github/ci/gitleaks.sh`: `--first-parent` を外し `--no-merges <base>..<head>` にする（`base..head` で base 側の既存履歴は除かれるので、範囲は PR 側の新しいコミットだけになる）
- `.github/workflows/ci.yml`: PR では `CI_SCAN_HEAD` を `github.event.pull_request.head.sha` にする（push は従来どおり `github.sha`）
- `.github/ci/run.test.mjs`: 期待する `--log-opts` を更新し、**実際の git 履歴**（base → PR 2 コミット → main 側の別コミット → merge）を作って、PR 先頭 sha・古い base＋マージ参照・merge push の 3 通りで、渡した範囲が PR のコミットを含むことを確かめるテストを追加
