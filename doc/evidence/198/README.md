## 自動調整がオンの時（指摘への対応）

端末が明るさを自動調整している間の実際の明るさを、Android の公開 API は返さない。設定値（`SCREEN_BRIGHTNESS`）は手動で決めた値で、画面の値とは別物。そのため読めない値として扱い、動かさずに理由を出す。

- `auto-on-swipe.txt`: 自動調整オン（設定値 102/255、表示 0.3976）で左半分を上へなぞっても、表示の明るさは 0.3976 のまま。値が飛ばない
- なぞると「端末が明るさを自動調整中で、いまの明るさを読めません。端末の設定で自動調整をオフにすると変えられます」を 3 秒出す（画面の読み上げ階層で文言を確認）
- `03-auto-on-panel.png`: パネルの明るさは「自動調整中のため明るさを読めません。端末の設定でオフにすると変えられます」と「--」。音量は通常どおり
- 自動調整をオフにすると上の通常の動きに戻る

注意: エミュレータには照度センサーが無く、自動調整オンでも表示の明るさは一定になる。実機で周囲の明るさに応じて表示が変わる状況は見ていない。

## 決めたこと: 自動調整中は明るさを動かさない

Android は既定で明るさの自動調整がオン。オンの間は、画面の実際の明るさを公開 API で読めない。設定値を起点にすると、表示と実際がずれて最初の一動きで値が飛ぶ。そこで動かさず、理由を出す（上の「自動調整がオンの時」）。

- 影響: 既定のままの端末では、明るさのスワイプとスライダーは使えない。音量は使える。#198 の「タップとスワイプで現在値から変える」は、自動調整をオフにした端末でだけ満たす。
- 戻し方: `MainActivity.kt` の `deviceBrightness()` で自動調整中も設定値を返す。その代わり、ずれた値が出て、最初の一動きで飛ぶことがある。
- 自動調整オンでのエミュレータ実測は `auto-on-swipe.txt` と `03-auto-on-panel.png`（設定値 102/255 のまま、0.3976 から動かない）。

## 案内の見え方（コントラスト）

画面の端の案内は、動画の上に黒の半透明を敷いて文字を置く。最悪は真っ白な動画。旧値（黒 40%、`white70`）は白動画の上で比が約 2.2 だった。`af8d697` で黒 60% と白文字にし、白動画の上で約 5.7（WCAG AA の 4.5 以上）。`video_view_test.dart` の計算テストで固定し、旧値に戻すと落ちる（変異検査）。エミュレータでの見た目の撮り直しはしていない。
