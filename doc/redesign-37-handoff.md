## 既知のギャップ（直していない。直すなら別タスク）
- **接続先を後から変える画面が無い**。接続の入力は未接続時の接続画面だけで、設定は表示だけ（元の実装も同じ）。写真タブの読み込み失敗の「接続先を確認する」は設定（接続先の表示）へ飛ぶだけ。
- **iOS のピッカーが `Documents/picked` に作る端末内コピー**が、確認シートのキャンセル・ドラッグ閉じで消えない（`MediaPicker.ios.kt`、元からの挙動）。
- **ロックの切替を素早く2回押すと保存順が前後し得る**（元は `MainScope().launch` で同じ）。
- 取り込みの検出バーは、検出が 0→N→0 と変わるたびにページの表示領域が約72dp伸び縮みする（ページに重ねないための代償）。
- 書き込めない保存先（読み取り専用、または一覧に無い）への積み込みは、`AppViewModel.upload`・`saveWeb` の入口でも拒否する（`canWriteTo`）。`TransferQueue` 自体には防御を置いていない。
- 確認シートの読み取り専用の文言は仕様の「読み取り専用は選べません」ではなく、理由が分かる長い文にしている。
- 接続画面の文言（「サーバーに接続」「接続せずに取り込みだけ使う」）は再設計で変えた。

### 実機で触る順（10分）
1. 写真タブ: 長押しで選択 → アルバムへ／オフライン／ゴミ箱へ → 「元に戻す」が6秒出て、戻すと一覧に復活する。
2. ビューア: 画像タップでバー開閉。動画は再生中にコントロールが消えるとバーも消え、タップで両方戻る。文字を最大にして、動画の再生バーが操作バーに隠れない。ゴミ箱へで閉じて「元に戻す」が出る。
3. ＋ → ピッカー → 確認シート（保存先・合計サイズ・先頭3件）→ アップロード。転送バーが下タブの上に出て、タップでシート。完了行は4秒で消える。
4. 機内モード: 待機中の転送が「オフライン（接続待ち）」になる。
5. 設定: ロックの切替・再ロック時間・今すぐロック（ロックOFFでは押せない）。ロック中に転送バーをタップしてもシートが開かない。
6. 取り込み: ページを開くと下に「N件のメディアを検出」の1行 → タップで一覧 → 保存。
7. 読み取り専用ライブラリ: 書き込み系が出ない。ゴミ箱は復元ボタンが出ない。取り込みの検出シートは「保存」が押せず理由が出る。
8. 取り込み: 検出バーが出る・消えるたびにページの表示領域が伸び縮みしても、ページの操作に支障が無いか。
9. 画面ロックが無い端末: 設定の「今すぐロック」が押せない。

## 判断して決めたこと（変えるなら理由を添えて）
- サイズ表記は `formatBytes`（1024基準、単位は MB/GB と表示）で全画面を統一。ゴミ箱の 3.4MB が 3.2 MB と出るのはこのため。
- 完了行の自動消去（4秒）は行だけを消し、完了通知（「N件アップロードしました」）の待ち行列は残す（`TransferQueue.dismiss(keepNotice = true)`）。手動の×は従来どおり通知も消す。
- 画面を離れても止めたくない処理は `withContext(NonCancellable)`（設定のロック切替・全削除・ゴミ箱の復元・ビューアのゴミ箱へ）。元の実装の `MainScope()` と同じ意図。
- ロック中は、前回までの転送行（`fromLedger`）を出さず、転送シートも開かない（`visibleTransfers`・Dock）。
- 設定の接続行は `hostOf` でホスト名だけ出す。最後の `@` までを先に落とすので、壊れた URL（userinfo に `/ ? #` が生で入る）でも認証情報は出ない。代わりに、パスに `@` を含む URL ではホストを誤って短く出すことがある（隠す側に倒した）。
- 取り込みの「保存」は、保存先が無い・未接続・読み取り専用のどれでも押せない（理由を出す）。検出バーはページに重ねず下に場所を取る。

## 証跡を作り直す
```
cd tools/render-harness && ./sync.sh && gradle --no-daemon -q render -Pout=/tmp/out -Ponly=<番号の接頭辞>
```
`sync.sh` が commonMain の「見た目だけの部品」をコピーする。新しい部品を足したら `sync.sh` の一覧に加える。
画面は状態を持つ `*Screen` と、描くだけの `*Content`／`*Parts` に分けてある。描くだけの側だけがハーネスに載る。
